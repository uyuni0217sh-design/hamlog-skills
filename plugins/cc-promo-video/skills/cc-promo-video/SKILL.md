# 클코 홍보영상 제작

편집 프로그램 없이 Claude Code에게 말로 시켜 홍보 영상을 만드는 흐름이에요. 기준 결과물은 뉴욕 워크숍 소개 영상 v26(1440×1080, 88초)이에요. 예시 파일에 나오는 「라이언」「햄로그」는 그 영상의 강사 이름이니, 새 영상에서는 사용자의 내용으로 바꿔요.

## 처음 한 번: 준비물

이 스킬을 처음 쓸 때(또는 렌더·받아쓰기 명령이 없다고 나올 때) 먼저 돌려요.

```bash
bash <이 스킬 폴더>/scripts/setup.sh
```

Node.js 22+, FFmpeg, HyperFrames(+렌더용 Chrome), 파이썬 Pillow, whisper-cli와 한국어 받아쓰기 모델(약 550MB, `~/.cc-promo-video/models/`에 저장)을 확인해서 **있으면 건너뛰고 없으면 설치**해요. 맥에서 Homebrew가 없으면 비밀번호가 필요해서 설치 명령만 알려 주니, 사용자에게 그 한 줄을 직접 실행해 달라고 해요. 받아쓰기가 필요 없으면 `--no-whisper`.

## 먼저 읽을 것

| 파일 | 내용 |
|---|---|
| `references/structure.md` | 13장면 구성표, 구성 이유, 만들 때 팁 |
| `references/design-rules.md` | 색·글꼴·자막·장면 장치·움직임·소리 규칙 |
| `references/tokens.json` | 색·글자 크기·여백 정확한 값 |
| `references/feedback-fixes.md` | 자주 나온 피드백 → 고친 방법 표 |
| `references/tech-recipes.md` | 렌더·디졸브·속삭임 끼워 넣기·카운트업·믹스 명령 |
| `templates/script-template.md` | 13장면 대본 빈칸 표 |
| `templates/example_index.html` | 실제 영상 HyperFrames 소스(GSAP 타임라인) |
| `templates/asset-list.md` | 장면별로 필요한 사진·영상 목록 |

## 작업 순서

1. **사실 모으기.** 행사 이름·날짜·장소·가격·신청 링크, 강사 활동명·공식 이력을 사용자에게 받거나, 사용자가 남겨 둔 메모·자료에서 찾아요. 이력은 사용자가 준 문구를 그대로 써요. 없는 숫자나 후기는 지어내지 않고 물어봐요. 실명은 화면에 넣지 않고 활동명만 써요.
2. **시안 여러 개.** 방향이 없으면 "시안 10개"를 짧게(장면 3~4개 스냅샷) 뽑아 고르게 해요. 고르는 게 만드는 것보다 쉬워요.
3. **대본.** `templates/script-template.md` 순서로 13장면 표를 써요(화면 제목 / 내레이션 / 자막). 화면 제목은 내레이션보다 짧게 줄여요. 장면 하나에 말 하나예요.
   - **사용자가 "오케이" 하기 전에는 녹음·렌더를 시작하지 않아요.** 대본을 고치는 중에 만들면 전부 다시 해야 해요.
   - 강사 소개 바로 뒤에 "배우면 할 수 있는 것"을 붙여요. 이력만 나열하면 자랑으로 끝나요.
   - 마지막 숫자 훅은 같은 숫자로 시작하는 말 세 개를 찾아요(2일 → 20년 → 2주 뒤).
4. **내레이션.** `~/.cc-promo-video/config.json`에 목소리 설정이 있으면 그대로 써요. 없으면 처음 한 번 사용자에게 물어서 이 스킬 폴더의 `config.example.json` 모양으로 그 자리에 만들어 둬요(스킬 폴더 안에 두면 업데이트할 때 지워져요).
   - 고를 것: ① 일레븐랩스에 만든 **내 클론 목소리**(voice_id), ② 일레븐랩스 **라이브러리 목소리**(마음에 드는 걸 같이 골라요), ③ **직접 녹음**(대본을 읽어 wav로 주면 그걸 써요).
   - 일레븐랩스 API 키는 파일에 적지 않아요. 환경 변수 `ELEVENLABS_API_KEY`나 일레븐랩스 MCP로 써요.
   - 모델은 `eleven_v4` 기준이고, 말투는 홍보 영상이라 해요체예요. 최종 녹음은 사용자가 웹에서 직접 들어 보고 뽑아 주는 게 제일 자연스러웠어요. 받으면 whisper-cli(`-l ko -mc 0`, 모델은 `~/.cc-promo-video/models/`)로 받아써서 문장별 시작·끝 시간을 표로 만들어요.
5. **화면 만들기.** `templates/example_index.html`을 복사해서 시작해요. 4:3(1440×1080), 어두운 톤, 강조색 하나, 에이투지체만. 장면 시간은 내레이션 문장 시간에 맞춰요(`show('#sN', 시작, 끝)`). 배경은 장면 뜻에 맞는 실제 사진·영상으로 바꿔요(인물 → 실내, 대표작 → 예고편 첫 장면, 결과 → 실제 작업 화면).
6. **스냅샷 확인.** `scripts/snap_sheet.sh "t1,t2,…" out.jpg 4`로 장면마다 한 장씩 뽑아 콘택트 시트로 보고 넘침·겹침·글자 크기를 고쳐요. 사용자에게도 시트를 먼저 보여주고 괜찮다고 하면 전체 렌더해요.
7. **렌더.** 내 컴퓨터에서 `npx hyperframes render`로 렌더해요(`references/tech-recipes.md`). 렌더는 백그라운드로 돌리고 로그의 `RENDERDONE`을 기다려요. 디스크가 1GB 아래면 거부되니 먼저 공간을 비워요.
8. **조립.** 인트로 영상 디졸브, 인트로 자막, 속삭임 반전 장면 끼워 넣기, 음악 덕킹 믹스, 폰용 압축본까지 `scripts/assemble_example.sh` 흐름대로 해요.
9. **검수.** 바뀐 구간 프레임 시트, 끝부분 받아쓰기(자막과 내레이션 일치), 길이를 확인하고 SendUserFile로 폰용을 보내요. 30MB 넘는 원본은 휴대폰으로 안 가니 폰용(960px, crf 25)을 같이 만들어요.
10. **피드백 반복.** 사용자는 "컷이 튀어", "글자가 떠 보여", "어지러워"처럼 느낌으로 말해요. `references/feedback-fixes.md`에서 해당 고침을 찾아 바로 적용하고, 버전 번호를 올려(v25 → v26) 다시 보내요. 이전 버전은 한두 개만 남기고 정리해서 디스크 공간을 지켜요.
11. **정리(요청 시).** "어떻게 만들었냐"는 질문에는 디자인 시스템 아티팩트로 답해요: README(디자인 규칙), 영상 구성, 이렇게 만들었어요(요청을 다듬어 옮긴 것), 내 영상에 쓰는 법, 컴포넌트 미리보기, 주요 장면. 남에게 보여줄 문서에는 날것 그대로의 말투·사적인 말·감정 표현을 빼고 요청 내용만 깔끔한 문장으로 옮겨요. 나눠줄 땐 스타터 키트 zip(대본 템플릿, 프롬프트, 예시 소스, 개인 사진 제외)도 만들어요.

## 지킬 것

- 화면 규칙: 4:3, 자막은 아래 가운데 흰색 50px 두 줄 이내, 자막 뒤 아래 그라데이션, 위쪽 태그 줄(날짜만 강조색), 오른쪽 위 진행 바(숫자 없이).
- 강조색은 한 장면에 크게 한 군데만. 주황 원색은 촌스럽다는 반응이라 앰버(#FFB547)를 기본으로 써요.
- 글꼴은 에이투지체 한 가족(`assets/fonts/`, SIL OFL 1.1 — `OFL.txt` 참고). 명조·이탤릭·손글씨는 쓰지 않아요. 다른 굵기가 필요하면 https://github.com/Freesentation/A2Z 에서 받아요.
- 꾸민 일러스트 말고 실제 얼굴·장소·결과물 사진을 써요. 남의 얼굴·작품은 허락받은 것만.
- 흔들리는 효과는 쓰지 않아요. 움직임이 필요하면 잔잔한 물결(7px, 1.8초)까지만.
- 효과음은 넣지 않아요. 음악은 한 곡을 끝까지 깔고 목소리에 덕킹, 끝 3.5초 페이드.
- 배속은 원래 속도. 1.2배는 너무 빠르다는 반응이었어요.
- 장면 사이 빈 화면이 끼지 않게 다음 장면 요소를 먼저 들여보내요.
